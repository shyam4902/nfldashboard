# Site audit, 2026-11-05

Branch `chore/site-audit`, cut from `main` at `0191229` (the NFL matchup, Teams and League merge). This covers the home page (`index.html`), `nba/` and `nfl/`. Each kind of fix has its own commit. Everything below that says "open" was left alone because the fix needs a design call or carries more risk than the audit justifies.

## How it was checked

The sandbox blocks ESPN, Supabase, `cdn.tailwindcss.com` and `cdn.jsdelivr.net`, so the pages ran in Playwright against stubs:

- Supabase, nflverse and espncdn go through `test-fixtures/supabase-fixtures.mjs`, the same fixtures `props-smoke.mjs` uses. Most NFL teams get the fixture's default colour (#3b82f6).
- ESPN calls are answered from `nba/fixtures/` and `design/polish/fixtures/`. Anything without a fixture gets a 404, so the NFL ESPN scoreboard shows its "live scores unavailable" state.
- Tailwind was built locally with `tailwindcss@3.4.17` (the play CDN runs v3) from `nfl/js/tailwind-config.js` and the config block in `nba/index.html`, scanning each page's markup and scripts. supabase-js came from the npm UMD build.

Routes covered: `/`, `/nfl/` plus `#schedule`, `#teams`, `#team/KC` (all three panels), `#league` (all three sub-tabs), `#matchup/<id>`, `#compare`, `#compare/KC/BUF` and `#player`, then `/nba/` plus `#standings`, `#standings/league`, `#leaders`, `#compare`, `#players`, `#game/<id>`, `#team/<id>` and `#player/<id>`, and `/404.html`. The NFL modals were opened by hand: roster, player profile, player compare, team compare, command palette and Matchups 101. All five NFL themes were checked for contrast.

`props-smoke.mjs` could not run here. It loads supabase-js from the CDN, so `DATA` never exists and the script stops with `ReferenceError: DATA is not defined`. Untouched `main` fails the same way in this sandbox. Run it on a machine with normal network before merging.

## 1. Links and hash routes

No broken internal link found.

- Every `href` on the three pages and in `nfl/js/` resolves to a file or a route the page's router handles. That includes `/nfl/#matchup/<game_id>` (`nflWeekGames` passes the `schedule.json` id that `openMatchup` looks up), `/nfl/#player/<ESPN id>` (`showNflPlayer` fetches the ESPN athlete), `#team/<abbr>/<panel>`, and `/nba/#scores/<yyyymmdd>`.
- Every `showTab(name)` target and command-palette entry has a matching `#tab-<name>` panel.
- `sitemap.xml` lists `/`, `/nfl/` and `/nba/`, which all exist.

Open:

- `nfl/js/core.js:207` uses `href="javascript:showTab('schedule')"`. It works only because `script-src` allows `'unsafe-inline'`. `href="#schedule"` does the same through the hash router and would survive a stricter CSP. Not changed because the marquee it sits in is home-page UI.
- `_redirects:25`, `:40`, `:55` and `:78` deny `/home-redesign.html`, `/test_projections.py`, `/scripts/debug_load.js` and `/moves_filtering.test.js`. None of those files exist any more. The rules do no harm and still protect the paths if the files come back, so they stay.
- `scripts/check_nfl_split.mjs:91` reads `<script src>` values as file paths. Since `nfl/index.html` added `?v=` to them, the harness dies with `ENOENT` on `nfl/js/tailwind-config.js?v=20261106a`. The header says it was a one-time proof for the split, so it may be time to delete it. That is the owner's call.

## 2. Contrast (WCAG AA)

Ratios come from `contrastRatio` in `nba/nba.js`, measured on every visible text node against its composited background. The thresholds are 4.5:1, or 3:1 for text that is 24px and up, or 18.66px and bold.

The home page and every NBA route pass at 390px and 1280px.

Fixed in `c36db05`:

- The NFL page footer (`nfl/index.html:343`) and two empty-value dashes (`nfl/js/schedule.js:772` and `:836`) used `text-slate-600` (#3d434c). In this palette that step is a border shade, and it measured 1.95:1 on the page. They now use `text-slate-500` (#868a91, 5.6:1). The analyst theme already overrides `.text-slate-500` for its light background.
- In the Stadium and ESPN themes, `--text-faint` (`nfl/nfl.css:58` and `:84`) measured 3.7 to 4.2:1 on the cards and failed in 55 places per theme. Each value now sits halfway between the theme's old `--text-faint` and its `--text-muted`. Stadium moved from #64748b to #7c8ca2, at least 4.7:1. ESPN moved from #6b7280 to #848b98, at least 4.65:1.

Open, default theme:

- `nfl/js/home.js:132` and `nfl/js/schedule.js:450` set the "FEATURED MATCHUP" kicker in white on the away team's colour. That fails for any mid-tone colour, for example 3.7:1 on #3b82f6.
- `nfl/js/home.js:139`, `:159` and `:167` set "AWAY", "HOME" and the big win % in the team colour on the dark hero. The Ravens' #6b3fa0 gives 2.6:1. The schedule hero repeats the pattern.
- `nfl/js/home.js:359` is the "WEEK N" pill: #e50914 on a 12% tint of itself, about 3.6:1. Unlike the two items above, the red is fixed. A lighter red would pass, but picking it is a design call.

The first two items take their colour from team data, so the ratio changes with the matchup. `nba/nba.js` already has the fix: `textOn(fill)` picks the ink for a fill, and `readableOn` adjusts a colour for a background. The home page and `/nba/` cards use them. Wiring them into `home.js` and `schedule.js` changes how the NFL hero looks, so I left it for whoever owns that hero.

Open, analyst theme (the light one, `nfl/nfl.css:124` onward). After the fixes it still has 53 failing pairs, and it needs its own pass. Its overrides cover the Tailwind classes but not the inline colours or the newer studio classes. Some examples:

- `.sch-team-abbr` (`nfl/nfl.css:883`) renders white on white on the home schedule cards.
- Schedule window titles (`.sch-window-title h3`) are white on #f8fafc.
- Team names on the schedule cards render #a2a5ab on white (2.5:1), and the favourite's win % renders #7cc49b on white (2.1:1).

The checker also reported dark-on-dark for the active tab and sub-tab in Stadium. That is a false positive. The background is a gradient (`nfl/nfl.css:342`), which the checker can't composite, and the real pairing is dark ink on amber.

## 5. Duplicate helpers between `nfl/nfl-lib.js` and `nba/nba.js`

`nfl-lib.js` already imports seven helpers from `nba.js`, `contrastRatio` and `textOn` among them. These private copies remain. The new `nfl/league-lib.js` adds a third copy of most of them:

| Helper | `nba/nba.js` | `nfl/nfl-lib.js` | `nfl/league-lib.js` | Notes |
|---|---|---|---|---|
| `arr` | 39 | 13 | 12 | identical |
| `str` | 43 | 17 | 16 | identical |
| `num` | 49 | 23 | 22 | identical |
| `timeOf` | 904 | 34 | 28 | `league-lib` returns `null` for a bad date. The other two return `0` |
| `hexOf` | 1021 | 435 | none | same results, different regex |
| team alias map | `NFL_ALIAS` at 1350 | `TO_LOCAL` at 43 | imports `localAbbr` | `nfl-lib` also maps `JAC` to `JAX` |

Not merged. To share them, `nba.js` would have to export four or five more names and both NFL libraries would have to import them. If a browser pairs a new `nfl-lib.js` with a cached `nba.js` that lacks those exports, the import fails and the NFL compare, player and League views break. That is the same stale-module failure the `_headers` comment describes for 2026-11-05. `/nba/*` is `no-cache` now, so the risk is small. Still, saving about 30 lines of five-line helpers doesn't justify it in an audit. If someone does it, the `timeOf` difference has to be settled first, and every `?v=` on the `nba.js`, `nfl-lib.js` and `league-lib.js` imports (`nfl/nfl-lib.js:9`, `nfl/league-lib.js:10`, `nfl/js/league.js:31` and `:32`, `nfl/js/views.js:25`) needs a bump in the same commit.

The alias gap is harmless today, since ESPN and nflverse both send `JAX`. Add `JAC: 'JAX'` to `NFL_ALIAS` if a feed ever sends the old code.

`pctText` is three different functions that share a name. `nba/nba.js:1709` turns a probability into "62%", or an empty string for null. `nfl/js/schedule.js:268` does the same but prints `'—'` for null. `nfl/league-lib.js:36` formats a win percentage as ".857". Each lives in its own scope, so nothing collides, but the shared name invites a wrong import. Separately, `nfl/js/schedule.js:258` to `:266` (`mlImplied`, `marketWinProb`) repeats the no-vig maths in `nba/nba.js:1670` to `:1683` (`mlImplied`, `mlWinProb`). The win % agrees.

## Cache note

The changed page files are `nfl/nfl.css`, `nfl/index.html`, five files in `nfl/js/` and `nba/index.html`. I left the `?v=20261106a` asset version alone. `_headers` serves `/nfl/*` and `/nba/*` as `no-cache`, so browsers revalidate on every load. The removed code was unreachable, so a stale copy behaves the same as a fresh one. The only visible changes are the colours in `c36db05`. Bump the version at merge time if you want those to land on the first load for everyone.
